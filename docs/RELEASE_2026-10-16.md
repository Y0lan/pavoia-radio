# GitHub publication, 16 October 2026

The website source includes the published roots footer, mobile stage controls,
photo selection, music discovery, listening history and statistics.

The Git review required these fixes before publication:

- An enabled station can use its cached playlist when all tracks remain reserved
  after a Liquidsoap restart. A successful enabled-status request does not clear
  this fallback condition. A successful track selection clears it.
- A successful enabled-status read also preserves a failed track-selection state
  until selection recovers. Removed track details remain available for delayed
  fallback callbacks for 96 hours, covering queued audio and callback retries.
- Playlist synchronization exports the fallback file after the database commit.
  A failed commit cannot expose an uncommitted playlist to Liquidsoap. If export
  fails after the commit, the previous cache remains until the next sync or
  controller startup rebuilds it.
- Discovery images require a current manifest entry and matching checksum.
  Both artwork caches reject incomplete images. Response writes release the
  artwork lock first, so slow clients cannot block other image requests.
  Deleted tracks also lose access to cached previews.
- Public discovery text removes filesystem paths, including connected records.
- Snapshot imports require checksums for all consumed files and reject duplicate
  records, invalid cursors or inconsistent stored counts.
- The local preview proxies the live audience endpoint.
- Media Session keeps unavailable radio metadata empty until a successful poll.
  An active preview retains its own metadata during radio status failures.
- Artwork retries temporary failures twice. Later metadata refreshes can retry
  persistent failures without rebuilding focused player controls.
- History retains its selected stage when returning from a track.
- History time bounds preserve fractions of milliseconds. Preview completion
  restores the radio playback state in Media Session.
- History, playlist changes and statistics release database connections before sending responses,
  so slow readers cannot hold the controller's only connection.
- At narrow desktop widths, playback status and time stack around the waveform
  so longer text cannot overlap Spotify controls.
- Audio acceptance uses separate test ports and the current Icecast config path.
  Browser checks use the current footer, audience endpoint and status state.

These runtime fixes are in the repository. They have not been deployed to
Whatbox. The website deployment remains the reviewed 15 October release.

Validation: backend race tests and Go vet; 13 player tests; operations,
load-check unit tests, catalogue inventory and discovery sync tests. The new
commit-failure test observes file rename events on Linux. The queue recovery
check runs the actual Liquidsoap selection function and fallback condition in
an isolated container. Both regression checks failed before their fixes.
Additional checks cover image corruption, manifest removal, response lock scope,
public metadata projection and Media Session recovery in Chromium.

Photos and fonts use Git LFS. A checkout requires `git lfs pull` before building.
